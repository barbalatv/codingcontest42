## Проверка

Из корня репозитория, без установки Python-зависимостей:

```sh
node research/2026-10-23-multiaccept/sandbox_probe.cjs
node validate_l6_sandbox.cjs
```

Первый скрипт проверяет сохранённые кандидаты, семантику клетки и циклы с 2–8 принятиями через оригинальный JavaScript песочницы. Он пишет только локальный `sandbox_results.json`. Второй проверяет итоговые файлы ответов.

## Повторный поиск

Требуется 64-битный Python с OR-Tools:

```sh
python -m pip install -r research/2026-10-23-multiaccept/requirements.txt
python -B research/2026-10-23-multiaccept/cp_probe.py --cases 36,159 --copies 2 --seconds 10
```

Многопоточный CP-SAT может найти другую программу или вернуть UNKNOWN при том же бюджете. Прототипы сохраняют свои результаты рядом со скриптами и не перезаписывают `answer_*.txt`.

## Данные

- `cases_latest.csv`: все 540 случаев, длины среза 9a89599, симметрии, статическая выполнимость и доказанные нижние границы. Название latest относится к моменту исследования.
- `inventory.json`: исторические паттерны, программы и трассы среза 2a90969 для воспроизведения экспериментов.
- `winning_programs.json`: четыре полные программы; `latest_before` относится к 9a89599.
- `probe_*.json`, `cegis_results.json`, `symmetry_results.json`: положительные и отрицательные результаты.

Номера случаев начинаются с единицы. OPTIMAL у задачи выполнимости с фиксированным горизонтом не доказывает глобальный оптимум; UNKNOWN не означает невозможность.
