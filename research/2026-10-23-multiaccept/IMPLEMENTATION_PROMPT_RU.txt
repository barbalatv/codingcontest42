Реализуй поиск периодических программ Level 6 с несколькими принятиями за период.

Контекст и исходная точка
Репозиторий https://github.com/barbalatv/-42, исследованный актуальный срез 9a89599. Все 540 случаев валидны в оригинальной песочнице, суммы 6334 / 6240 / 6488, всего 19062. Сначала проверь текущий HEAD и не заменяй более короткие ответы устаревшими. Не создавай коммитов, PR и не отправляй ответы на платформу. Все новые ответы сначала сохраняй отдельно от answer_*.txt.

Исследование и воспроизводимые свидетели находятся в:
research/2026-10-23-multiaccept
Файлы: REPORT_RU.md, cp_probe.py, winning_programs.json, sandbox_probe.cjs, sandbox_results.json, cases_latest.csv. Прототип использует OR-Tools из requirements.txt; он не является готовым оптимизатором всего набора.

Проблема существующей реализации
phase2_cycle_cp.py::extract допускает только одно принятие между одинаковыми позами. solve_loop в строках 50–66 моделирует один паттерн, требует целевое конечное поле и запрещает промежуточные принятия. phase2_beam.cpp::search завершается при первом принятии; main ищет следующие копии последовательно, и повторение позы обнаруживается лишь постфактум. Поэтому эти методы не оптимизируют совместно среднее число тактов на несколько принятий.

Точная модель
Пусть P — целевые клетки, F — соседняя кайма, R=P union F. Только R необходима для планирования: лучи не блокируются материей. После каждого принятия R пуста. Состояние между тактами: шесть позиций modulo 6*r, шесть флагов активности, маска материи R, счётчик принятий. Используй существующие solve_l4.geometry, solve_l6.origins/delta и optimize_l6_compact.Sim, не подменяя геометрию.

За такт у каждого эмиттера ровно одна из F/B/T/-. После применения всех команд для каждой клетки посчитай число лучей h. При h==2 материя устанавливается, при h>=3 удаляется, иначе сохраняется. Затем acceptance = AND(P occupied) AND AND(F empty). После acceptance обнули только P, увеличь счётчик. Никакой отдельной команды принятия нет.

Требуемое изменение
1. Обобщи извлечение циклов на любое число принятий q от 1 до 8 между одинаковыми (positions, active). Сохраняй стоимость, число копий, начальную фазу и префикс, а не только длину.
2. Добавь точный CP-SAT solve_multi_loop(case,start,H,q,offset,limit).
   Для каждого такта введи pre_presence, post_presence и accept[t].
   accept[t] должен быть эквивалентен точному условию принятия, а не только импликацией.
   Для P: post=pre AND NOT accept. Для F: post=pre.
   Начальная и конечная маски R равны нулю, позиции/активность замыкаются, sum(accept)=q. Промежуточные принятия разрешены.
   Переход позиции на -1/0/+1 допустим только без смены активности, а смена активности — только при неизменной позиции. Активный эмиттер может двигаться и светит уже из новой позиции.
3. Первые пробы: medium cases 36 и 159, H=11,q=2,offset=0, якорь — поза после первого принятия исходной программы. Затем 108 и 204, H=9,q=2.
   Подтверждённые результаты: 104->96, 92->85, 82->74, 81->74. Значения кандидатов и полные программы есть в winning_programs.json.
4. Выбирай горизонт по средней стоимости конкретного исходного цикла. Максимальный промежуток между принятиями может давать заведомо невыгодную цель: прототип получил корректные, но худшие ответы для medium 120 и 145.
5. Оптимизируй конечное число требуемых копий: стоимость префикса + полные периоды + лучший хвост. Тримминг строго на K-м принятии. Никогда не принимай кандидата по одному отношению H/q без сравнения полной длины.
6. Не сбрасывай произвольно эмиттеры после каждого принятия. При свободном якоре включай реальную стоимость его достижения и проверь первый цикл из достижимого состояния.
7. Для больших горизонтов сначала поддержи граф нескольких поз принятия и поиск коротких переходов между ними; не увеличивай просто timeout или beam width. DP по числу принятий выбирает комбинацию переходов; для больших K можно использовать minimum-mean-cycle как ориентир.
8. Сохраняющаяся материя вне R может меняться в первый период. Повторение фиксированного периода задаёт на каждой такой клетке identity или присваивание константы, поэтому стабилизируется за один период. Валидируй два периода после прогрева по ВСЕЙ материи и эмиттерам, если заявляешь полный замкнутый цикл.

Валидация и ограничения
Финальный критерий — неизменённые parsing/geometry/applyEmitterStep/testPattern/acceptAndDeletePattern из level-6/sandbox-level-6.html, как в validate_l6_sandbox.cjs. Проверяй точное K и все шесть инструкций на строку. Статус CP-SAT OPTIMAL у задачи выполнимости с фиксированным H не доказывает глобально кратчайший цикл; UNKNOWN не означает невозможность.

Первый результат реализации — четыре отдельных улучшенных программы и сравнительная таблица к ТЕКУЩИМ ответам. После успешной проверки можно расширить короткий пилот на medium с K>=8 и на несколько large. Enormous имеет K<=2, поэтому там нужен открытый путь из начального состояния, а не навязывание замкнутого цикла. Не обещай score 15000 без измерений.
