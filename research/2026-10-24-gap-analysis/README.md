# Level 6 gap analysis toolkit

Инструменты и результаты анализа: «почему очки встали и где лежат недостающие такты».
Главный документ — **[REPORT_RU.md](REPORT_RU.md)**.

## Что здесь есть

| Файл | Назначение |
|---|---|
| `REPORT_RU.md` | разбор: геометрия уровня, замеры, резервы по кейсам, план действий |
| `headroom.csv` | по всем 540 кейсам: T, K, nT, ёмкость кисти, нижняя граница, `excess` |
| `worklist_top.csv` | 99 кейсов с резервом ≥ 10 (суммарно 1840 тактов) — приоритетный фронт работ |
| `summary.json` | агрегаты по группам (набор × K) |
| `case_stats.json` | подробная статистика по кейсам (интервалы, плотности, idle, kills) |
| `sim.py` | точная битовая модель уровня: сжатие до `target ∪ skirting`, трассировка |
| `dump.py` | выгрузка 540 кейсов в `cases.txt` для C++ инструментов |
| `stats.py` | пересчёт `case_stats.json` |
| `brush.cpp` | ёмкость кисти: максимум target-клеток от одной позы (сэмплинг) |
| `brush_seeds.cpp` | библиотека «чистых штампов»: поза + покрытие, top-N на кейс |
| `cycle_sa.cpp` | SA по блокам `p` тактов (без замыкания, оценка на повторениях) |
| `beam.cpp` | chained-beam строитель — в этой задаче не сработал, см. §7 отчёта |
| `cp_copy.py` | CP-SAT: минимальная длина одной копии из заданного состояния |
| `cp_cycle.py` | CP-SAT: оптимальный замкнутый цикл периода `p` (с доказательствами) |
| `cp_plan.py` | CP-SAT: свободный старт, максимум принятий за `p` тактов |
| `verifyall.cpp` | быстрая перекрёстная проверка модели на всех 540 ответах |

## Воспроизведение

```bash
cd research/2026-10-24-gap-analysis
python3 dump.py                        # cases.txt
g++ -O2 -march=native -o brush_seeds brush_seeds.cpp
./brush_seeds 200000 5 0 540           # чистые штампы по всем кейсам
python3 cp_copy.py large 143 3 20      # можно ли large #144 скопировать за 1..3 такта
python3 cp_cycle.py medium 0 3 20      # оптимальный замкнутый цикл (OPTIMAL/UNKNOWN)
```

Требуется `g++`, `python3` и `pip install ortools` (только для `cp_*.py`).

## Цифры на текущих файлах ответов

* 15657 тактов, 540 кейсов, 2944 принятия (Python-модель и JS-песочница совпадают).
* Плотность рисования ≈ 4.1 target-клетки за такт; одна поза физически даёт 5–20.
* Измеренный резерв ≈ 2375 тактов (15.2 %), из них 1952 — в `large K≥3`,
  `enormous K=1`, `enormous K=2`. `medium K≥3` почти исчерпан (4.6 %).
* 28.8 % программ (81 % в enormous) — чистый дрейф без замкнутого цикла.

Сгенерированные артефакты (`cases.txt`, скомпилированные бинарники) в Git не попадают.
